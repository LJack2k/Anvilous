Pack-making release. Nothing about how the smithing table behaves has changed, and the 169
built-in recipes do the same thing they did in 0.1.0.

### Generated packs now work in a modpack

`dump_repair`, `dump_combine` and `dump_enchant` named each file after the item's path alone.
That is unique in vanilla, because vanilla is one namespace. In a modpack it is not: two mods
owning a `steel_pickaxe` wrote the same filename and the second quietly won, so a modded
export came out short with nothing in the log to say so.

Recipes are now filed in a folder per namespace, which cannot collide. It also gives the
export a shape you can work with, since one mod's recipes are one folder to keep or drop as
a unit.

### One generated pack, shippable to every pack you make

Everything the generators write that is not vanilla now carries a `neoforge:conditions` block:

```json
{
  "neoforge:conditions": [
    { "type": "neoforge:item_exists", "item": "mekanism:steel_pickaxe" }
  ],
  "type": "anvilous:smithing_repair",
```

So a Mekanism recipe simply does not load where Mekanism is absent. Generate once in your
largest pack and reuse the output across the rest, rather than maintaining a set per pack.

Repair and combine key on the item rather than the mod, because the item is the recipe's real
dependency and mods do not keep their items in the jar you would guess: Mekanism's tools are
in MekanismTools, Mystical Agriculture's in Agradditions. Enchanting keys on `mod_loaded`,
there being no `enchantment_exists` condition to use. Vanilla gets no condition at all.

### Breaking: recipe paths moved

The three built-in sets moved to the same per-namespace layout, because the built-ins and the
generators have to agree on paths. If they did not, your own file would stop replacing the
built-in copy and would quietly become a second recipe instead.

That means recipe ids changed:

- `anvilous:diamond_pickaxe` is now `anvilous:minecraft/diamond_pickaxe`
- to override a built-in, ship `data/anvilous/recipe/minecraft/diamond_pickaxe.json`

If you wrote an override against a 0.1.0 path, move it into a `minecraft/` folder. Nothing
else is affected, and the recipes themselves are unchanged.
